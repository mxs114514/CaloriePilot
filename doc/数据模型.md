# CaloriePilot 数据模型文档

## 一、数据存储原则

第一版采用本地存储方案，业务数据保存在浏览器 IndexedDB 中。

数据模型设计遵循以下原则：

- 用户输入的数据需要持久化保存。
- 可以由已有数据计算得出的结果，默认不重复存储。
- 历史记录按日期组织，便于记录页和历史页读取。
- 字段命名面向后续 TypeScript 类型定义，保持清晰稳定。

## 二、用户资料 UserProfile

用于保存用户基础信息和个性偏好。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | string | 是 | 用户资料唯一标识，本地单用户场景可固定为 `default` |
| name | string | 是 | 姓名 |
| gender | Gender | 是 | 性别 |
| age | number | 是 | 年龄，单位：岁 |
| heightCm | number | 是 | 身高，单位：厘米 |
| currentWeightKg | number | 是 | 当前体重，单位：千克 |
| dietPreference | DietPreference | 是 | 饮食习惯 |
| activityLevel | ActivityLevel | 是 | 运动强度 |
| createdAt | string | 是 | 创建时间，ISO 字符串 |
| updatedAt | string | 是 | 更新时间，ISO 字符串 |

### 枚举说明

Gender：

- male：男
- female：女

DietPreference：

- light：清淡
- normal：正常
- highProtein：高蛋白
- lowCarb：低碳水

ActivityLevel：

- low：低
- medium：中
- high：高

## 三、计划信息 GoalPlan

用于保存用户的减重计划。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | string | 是 | 计划唯一标识 |
| startDate | string | 是 | 计划开始日期，格式：YYYY-MM-DD |
| durationDays | number | 是 | 计划时长，单位：天 |
| weightLossTargetKg | number | 是 | 减重目标，单位：千克 |
| dailyCalorieTarget | number | 是 | 每日热量目标，单位：kcal |
| createdAt | string | 是 | 创建时间，ISO 字符串 |
| updatedAt | string | 是 | 更新时间，ISO 字符串 |

### 说明

- `dailyCalorieTarget` 由计算规则生成，用于记录页展示今日目标。
- 第一版默认同一时间只有一个当前计划。

## 四、热量记录 CalorieRecord

用于保存用户每餐热量摄入。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | string | 是 | 热量记录唯一标识 |
| date | string | 是 | 记录日期，格式：YYYY-MM-DD |
| mealType | MealType | 是 | 餐次 |
| calories | number | 是 | 摄入热量，单位：kcal |
| createdAt | string | 是 | 创建时间，ISO 字符串 |
| updatedAt | string | 是 | 更新时间，ISO 字符串 |

### 枚举说明

MealType：

- breakfast：早餐
- lunch：午餐
- dinner：晚餐
- snack：加餐

## 五、体重记录 WeightRecord

用于保存用户每日体重。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | string | 是 | 体重记录唯一标识 |
| date | string | 是 | 记录日期，格式：YYYY-MM-DD |
| weightKg | number | 是 | 体重，单位：千克 |
| createdAt | string | 是 | 创建时间，ISO 字符串 |
| updatedAt | string | 是 | 更新时间，ISO 字符串 |

### 说明

- 同一天可以按产品实现策略保留一条最终体重记录。
- 历史页按日期展示体重变化趋势。

## 六、计划事项 PlanItem

用于保存计划清单中展示的日程事项。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | string | 是 | 计划事项唯一标识 |
| title | string | 是 | 计划事项名称 |
| createdAt | string | 是 | 创建时间，ISO 字符串 |
| updatedAt | string | 是 | 更新时间，ISO 字符串 |

### 说明

- 第一版计划清单只关注事项展示和打卡。
- 计划事项的来源由产品流程决定，数据层只保存可展示、可打卡的事项。

## 七、计划打卡记录 PlanCheckin

用于保存计划事项在某一天的完成情况。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | string | 是 | 打卡记录唯一标识 |
| date | string | 是 | 打卡日期，格式：YYYY-MM-DD |
| planItemId | string | 是 | 对应计划事项 ID |
| isCompleted | boolean | 是 | 是否完成 |
| completedAt | string | 否 | 完成时间，ISO 字符串 |
| createdAt | string | 是 | 创建时间，ISO 字符串 |
| updatedAt | string | 是 | 更新时间，ISO 字符串 |

## 八、派生数据

以下数据由计算规则实时计算，不作为独立业务表保存：

- BMI 指数
- 今日已摄入热量
- 今日剩余可摄入热量
- 今日当前缺口
- 每日摄入热量汇总

## 九、数据关系

- UserProfile 提供基础身体信息和偏好信息。
- GoalPlan 基于 UserProfile 生成每日热量目标。
- CalorieRecord 形成每日摄入热量汇总。
- WeightRecord 形成每日体重趋势。
- PlanItem 和 PlanCheckin 形成计划清单完成状态。
- 历史页读取 CalorieRecord 和 WeightRecord 生成折线图数据。
